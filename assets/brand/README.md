# kondo アイコン

`symbol.svg` が文字なしの正本。O案からミシン目をなくし、旅の軌跡・出発点・ピンだけを残す。

## 現行デザイン

- 採用版S：ユーザーが選んだB案（FLOW）。左上の出発点、上の実線、下の丸端の破線、右下の目的地ピンで「こ」と旅の軌跡を表す。
- 上の実線の右端を短く左下へ返し、下の破線の入り口も同じ向きにする。二画の間には線を描かず、筆運びを余白で感じさせる。「乙」のような一続きの斜線にはしない。
- 描線は上34px・下26px、出発点は半径32px（模様座標基準、1024px出力では2倍）。下は5本の丸端の破線で、線分と隙間を等間隔に配置する。
- ピンは塗りつぶし、中央の半径14pxの円を偶奇塗りで抜く。ダーク用・単色用でも円の穴が残る。
- キャンバスは透過。ホーム画面はこれまでと同じ黒い模様＋片側4pxの白縁で、ライト／ダークとも同一画像を使う。背景合成プレビューは `proposals/journey-light-dark.png`。
- アプリ内だけはダークモードで白い模様へ切り替える。`public/logo-dark.svg` は白縁の下地を除き、ピンの穴と二画の間を透過にする。プレビューは `proposals/adopted-app-themes.png`。
- 起動アニメーションも同じパス・太さ・破線・ピンに揃える。上240ms・下260msの描画と、続くピンの揺れ・文字の出現は維持する。
- 配信画像はv13。旧v12（採用版R）以前は比較用に固定し、上書きしない。
- 合成プレビューとiPhoneの背景自動切替は別。採用版Sの実機切替・既存ホーム画面アイコンの更新時期は未確認。

## iPhoneで成功した方式（2026-09-24実機確認）

ユーザーのスクリーンショットで、比較H・Iともライトで白背景、ダークで黒いグラデーションへ切り替わることを確認した。
比較Iは現在のチケットデザインの基準。成功したデータは変更せず保存する。

- SVG: `scripts/fixtures/kondo-cutout-source.svg`
- 配信され、実機で確認されたPNG: `scripts/fixtures/kondo-cutout-touch.png`
- PNG SHA-256: `d6afe65c476c06d20fa0854789f711dff6bc488ca07e88adb324736c3b1771a0`
- 成功時の配色: 前面`#656565`、背面`#E0E0E0`
- 成功時の配置: 前面`rotate(-10 525 490)`、背面`translate(-28 44) rotate(-10 525 490)`

### 再現手順

1. 背景に白や黒の面を描かない。全体を透過キャンバスとする。
2. チケット2枚を色の付いた面として描く。外周に不透明な縁取りを加えない。
3. 軌跡やピンを不透明な色で上描きせず、SVGの輝度マスクで穴にする。マスクは2枚をまとめたグループへ適用し、背面の紙も一緒に切り抜く。
4. マスク定義内の白い矩形はマスクを通す領域であり、表示する白背景ではない。SVGを書き出す際は`<defs>`と`mask`参照を両方残す。単色アイコンへの変換でも、マスク内部の黒／白を塗り替えない。
5. `scripts/render-touch-icon.mjs`で、SVGをdensity 384で読み込み、180×180へ縮小。PNGはcompressionLevel 9、palette falseのRGBA。`flatten()`や`removeAlpha()`を使わない。
6. `apple-touch-icon`でその透過PNGを指定する。比較ページではmanifestも同じ画像を指す。アプリ内のテーマ切替で別画像へ交換しない。
7. `node scripts/test-icon-check.mjs`で、成功したIのSVGからPNGを完全再現できること、成功版Iの背景と模様の穴が透明なことを確認する。

| I（縁取りなし・模様を透過で切り抜いたチケット） | 白 | 黒 |

Iへの変更は縁取りの除去と模様の切り抜きを含むため、iOS内部の判定条件や唯一の原因を断定しない。
調整版Kは前面を白、背面をグレーにし、2枚の角度差を20度にしたもの。ユーザーの実機画像ではライトの背景は白になるが、白い前面と模様が背景に溶け込むことを確認した。Kのダーク表示は未記録。
調整版LはKの白い面を維持し、外周と模様の穴の周囲にグレーの縁を追加した。穴の中心は2枚を貫く透過のまま。白／黒背景での合成プレビューとアルファを確認する。Iの成功とLの実機での自動切替は区別し、Lの実機表示は未確認とする。成功版Iの再現手順・データは変更しない。
調整版Mはユーザーの指定で縁取りと模様を黒にし、模様の切り抜きを廃止した。白い前面・グレーの背面・角度差20度は維持。Iの方式とは区別し、iPhoneでの背景切替は未確認。
調整版Nはピンの外周線を14px、中央円の線を12px（半径10px）へ戻した。Mでは透過の穴の縁取り用の太い線幅26px／24pxが残ってしまい、中央の円がつぶれていた。模様の黒塗りとチケットの配置は維持。
別案O（`proposals/journey-perforation.svg`）はチケットの外形をなくし、旅の模様を2倍に拡大。右端に傾けたグレーのミシン目を置き、キャンバス外で見切れる構図にした。Oは比較用のみで、通常アプリのアイコンには適用しない。N・Oの実機での背景切替は未確認。
調整版PはOのミシン目を取り除き、白い細縁で黒背景での視認性を確保した。旧N・Oのデータと比較プレビューは保存し、上書きしない。
採用案Qは下を丸い点線にしたもの。通常アプリのアイコンに適用し、アプリ内だけダーク用の白いロゴを使う。
採用版RはQの丸い点をカーブに沿って少し伸ばし、短い丸端の破線にした。アプリ内のダークモードでは白い線、ホーム画面では黒い線＋白縁という配色は維持。
再追加だけで直る、画像URLを変えれば外観が必ず切り替わる、透過PNGなら何でも切り替わる、とは扱わない。

## 生成と配信

`npm run icons:export`でSVG原本からPNG・SVG・ICOを再生成する。PNGを直接編集しない。

- `icon*.png`／`logo*.png`: 1024px、背景は透過、模様は不透明な黒と白縁。
- `adaptive-foreground.png`: Android用、セーフエリア内へ縮小。
- `adaptive-monochrome.png`: すべての塗り面を白へ変更したシルエット。
- PWA manifest: `/icons/kondo-icon-v13-192.png`、`-512.png`、`-maskable-512.png`。
- Apple Touch Icon: `/icons/kondo-apple-touch-icon-v13.png`（180px・透過）。
- `icon*-dark`・`apple-touch-icon-dark`は通常アイコンと同じデータ。`logo-dark`と`symbol-dark`だけはアプリ内用の白い模様。
- 以前のv3/v4/v5/v6/v7/v8/v9/v10/v11/v12画像と実機確認用fixturesは上書きしない。

`EXPO_PUBLIC_ENABLE_DEMO=true npm run build:web`でstaging用の比較ページを生成する。採用版Sと過去の比較案を別IDで表示する。
通常アプリのmanifest ID・保存キーは変更しない。インストール済みアイコンの更新時期は別途端末で確認する。
