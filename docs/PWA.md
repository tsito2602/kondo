# PWA

主な利用対象はiPhone・Pixelのホーム画面に追加したWebアプリ。Expo SDK 57のWeb出力と既存のCloudflare Workers / D1 / R2を使用する。既存のフォーム、予約、乗り継ぎ、認証、同期を維持できるため、今回はDOMへの全面移行やHonoの追加を行わない。

## 開発・配布

- 開発: `npm run web`
- 検証とPWA生成: `npm run check`
- Web生成のみ: `npm run build:web`
- `dist`にmanifest、ホーム画面アイコン、Service Workerが含まれる。
- Service Workerはproduction buildのみ登録。HTTPSまたはlocalhostで配信する。
- stagingへのpushが既存CIと自動デプロイを起動する。ネイティブのプレビュー生成は主な配布経路にしない。

## 起動・更新・保存

初回オンライン起動時に公開アプリシェルとビルドアセットをバージョン単位で保存する。APIレスポンスはService Workerにキャッシュしない。新バージョンは待機し、旅行一覧の「新しいバージョンに更新」で適用する。未送信の変更がある場合は更新できない。

旅行・場所・予約・準備と未送信操作はアカウント別IndexedDBに保存。旧localStorageデータは既存セッションの所有者が確認できた場合に移行する。サンプルも独立保存する。再接続・画面復帰・起動時に同期する。

ログイン済みユーザーは端末のセッションと期限付きユーザー情報で圏外でもローカルデータを開ける。サーバー処理は毎回セッション検証する。ネットワークエラーを理由にログアウトしない。401/403ではローカル認証を解除する。

「オフライン保存」は現在の旅行データの永続化を待ち、最新スナップショットの画像・PDFを順次IndexedDBへ保存する。保存失敗は完了として扱わない。訪問先の外部リンクや地図はオフライン保存の対象外。端末データはOSの容量不足等で削除される場合があるため、旅行前にオンラインで保存状態を確認する。

## 旅行・場所

- 旅行画像は端末で縮小・JPEG圧縮し、55万文字以内のdata URLで保存。`trip_covers`は追加テーブルなので既存旅行を変更せず導入できる。
- 場所の訪問ステータスと予約状況は別管理。場所から訪問日を選んでしおりに予定を作成できる。両者は独立した記録で、以後の編集は自動連動しない。
- 旅行編集は共有メンバーが可能。旅行削除は作成者のみ、オンラインで未同期操作を処理してから実行する。子テーブルは外部キーで削除、R2書類も削除する。
- ステージングと本番のデータは既存設定のとおり分離する。

## 検証

`check`は型・Lint、既存接続/同期テスト、Places APIのCRUD・権限・再送・画像保持・旅行削除、Service Workerの圏外ルート復帰・更新待機・API除外を検証する。実機でのホーム画面追加とSafariのOS挙動は別途確認が必要。
