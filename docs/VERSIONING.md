# バージョン番号の付け方

決めた日: 2026-11-11（Tsubasa）

kondo のバージョンは `メジャー.マイナー.パッチ` の3つの数字で表します。番号は `package.json` の `version` に書き、本番（`main`）に出すたびに1回だけ上げます。コミットの数では上げません。

## どの数字を上げるか

| 数字 | 上げるとき | 例 |
|---|---|---|
| メジャー | 見た目や使い方がまるごと変わるとき（2.0.0 のリデザイン級）。または、古いアプリが新しいデータを読めなくなるとき | 2.0.0 リデザイン |
| マイナー | できることが増える、または減るとき。新しい画面や機能、ログイン方法の変更、機能の削除 | 2.5.0 AI用のキーとMCP、2.6.0 しおりをPDFや画像で渡す |
| パッチ | 今ある機能の直し、見た目や動きの調整 | 2.4.1 フォントを端末の標準に |

1回の公開に複数の変更が入るときは、いちばん大きい段階に合わせます。マイナーを上げたらパッチは 0 に、メジャーを上げたらマイナーとパッチを 0 に戻します。

## 誰がいつ上げるか

- 本番に出す PR の中で `package.json` と `package-lock.json` の `version` を上げます。PR の説明に、どの段階にしたかと理由を1行書きます。
- Tsubasa が main にマージした時点でその番号に決まります。判断が割れそうなときは、マージ前に Tsubasa に確認します。

## 画面に出る番号

- 本番: `package.json` の番号そのまま（例 `2.6.0`）。
- staging と手元のビルド: その番号のあとに、番号を上げてからのコミット数を付けます（例 `2.6.0 (3)`。staging という言葉は付けません）。PR で番号を上げていれば、staging では次に出る番号が見えます。
- 計算は `vite.config.ts` の `buildVersion()` です。`VITE_APP_VERSION` を渡すとそれが優先されます。
