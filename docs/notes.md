# メモの要件

- 旅行ごとの共有メモ。owner/editorは編集、viewerは閲覧のみ。
- タイトル（任意・120文字以内）と本文（50,000文字以内）を分ける。タイトルだけ・本文だけでも保存できる。何も入力せず閉じた新規メモは作成しない。
- 一覧は更新の新しい順。タイトル、本文の抜粋、更新日を表示し、タイトルと本文を検索する。固定・固定順・アーカイブ・ラベル・色分けは設けない。
- 本文は通常のテキストエリア。プレースホルダーは「メモを入力...」。文字装飾・リスト変換・チェックボックスなどの編集ツールは設けない。
- 変更は自動保存。完了・閉じるでも保留中の入力を保存し、既存の端末保存・未送信キューでオフライン編集を維持する。共有時の競合解決は既存と同じ後勝ちで、同時編集の文字単位マージは対象外。
- 開いた直後は入力欄をフォーカスせず、ボトム操作とアプリ共通のフローティング画面を使う。
- 削除は確認を挟み、自動保存で復活させない。

## データ互換性

- `travel_notes.body`に通常のテキスト、`note_details`にタイトルを保存する。以前の書式JSONはAPI互換性のため読み込み可能だが、新しい画面で保存するときは解除する。
- 既存メモは保存済みのテキスト本文をそのまま表示し、チェックリストの項目・完了記号や改行も残す。タイトルの設定は任意。
- スキーマ適用は繰り返し可能な追加テーブルのみ。既存の固定値は表示・並び順に使わない。
- 古いアプリから本文が更新された場合はタイトルを維持し、古い書式JSONを破棄して最新の本文を優先する。
